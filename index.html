Click Fix Demo

ClickFix is social engineering that gets a visitor to fix a fake problem themselves — by opening the Windows Run dialog and pasting a command copied from a page. The “fix” is the infection. This demo reproduces four common lures and performs a real clipboard write for each, so you can point clipboard protection at it and watch the interception happen live.

  • HTTPS-only — secure context required
  • No external requests — fully client-side
  • Defanged payloads — inert even if run

02 — Demoing your extension

Compare both protection modes

This page’s job is always the same: attempt a real clipboard write. What happens to that write depends entirely on how the extension is configured — switch modes in its options and re-run the “Copy fix command” step above to show the difference live.

Mode 01

Clipboard API Only

Blocks every programmatic clipboard write, unconditionally — content is never inspected.

  • Expected result here: the write attempt above fails or is silently dropped every time, regardless of scenario.
  • Blind spot to call out: a lure that asks the target to manually select and copy text (no script involved) still gets through in this mode — that’s the Manual copy scenario above. Mode 02 still catches it, because it inspects clipboard contents no matter how they got there.
Mode 02

AI Classifier

Lets the write land, immediately quarantines the clipboard behind a placeholder, screens the text with local heuristics and a cloud classifier, then restores it if benign.

  • Expected result here: click “Check clipboard now” right after copying and again a moment later — you should see the placeholder, then a final verdict, since every payload here mirrors a real ClickFix command.
  • What it catches that Mode 01 misses: nothing extra for scripted copies — this mode is about deciding intent, not just blocking the mechanism.
